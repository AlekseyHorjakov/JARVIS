# Соглашения по проекту

Документ определяет единые соглашения, используемые при разработке JARVIS.

---

## Именование

### Папки

Для всех папок используется **lower_snake_case**.

Примеры:

- architecture
- assets
- automation
- config
- core
- docs
- prompts
- scripts
- skills
- storage

---

### Документы

Основные документы проекта используют **UPPER_SNAKE_CASE** или общепринятые названия.

Примеры:

- README.md
- CHANGELOG.md
- ROADMAP.md
- STACK.md
- CHANGE_POLICY.md
- CONVENTIONS.md
- VISION.md

---

### Остальные файлы

Используется **snake_case**.

Примеры:

- long_term_memory.sql
- resolve_ontology.sql
- recall_memory.md
- deploy_core.py
- memory_classifier.json

---

### База данных

Таблицы, функции и поля именуются в **snake_case**.

Примеры:

- user_memory
- memory_ontology
- memory_ontology_aliases
- jarvis_config
- resolve_ontology()
- canonical_key

---

Основная ветка:

```text
main
```

## Кодировка

Для всех файлов используется **UTF-8**.

---

## Язык

- Документация — русский.
- Код — английский.
- Имена таблиц, функций, переменных и файлов — английский.

---

## Архитектурные соглашения

- JARVIS Core не зависит от внешних интерфейсов.
- Все входящие данные проходят через Input Gateway.
- Внутренние модули работают с единым форматом сообщений.
- Новые модули подключаются без изменения существующей архитектуры.
- Компоненты должны быть максимально независимы друг от друга.

---

## Документирование

- Каждый завершённый функциональный модуль отражается в документации.
- Документация должна соответствовать текущему состоянию проекта.
- Не документируется функциональность, которая ещё не реализована.
